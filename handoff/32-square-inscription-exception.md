# 32 · daniel-5-1: the real inscription of Daniel 5:25 (per-square exception)

Owner ruling 2026-11-03: the registry demand (luminous writing on the wall) and the `fakeText` veto contradicted each other; the Bible governs. The writing is shown, as the real words of Daniel 5:25: מְנֵא מְנֵא תְּקֵל וּפַרְסִין (Mene, Mene, Tekel, Upharsin; read in 5:26-28 as MENE, TEKEL, PERES). Daniel 5:5 says fingers of a man's hand wrote opposite the lampstand on the plaster of the palace wall; no text says it glowed, so the letters are incised and lit by the lampstand, with a restrained pale gold edge glow (the registry already demands luminous).

## Design: the generator never draws letters

1. `live/daniel-5-1.png` (the text-free derivative) stays text-free. It shows the disembodied hand and a large BLANK, evenly lit plaster area. `fakeText` (veto table, SHA `veto-v1-2026-10-23`, unchanged) judges it exactly as every other square; OCR must still be 0.
2. After the live picture passes, `tools/scenes/composite_inscription.py daniel-5-1` draws the letters with a real font and writes `no-text-derivatives-v2/inscribed/daniel-5-1.png` + `.inscription.json` (base SHA, output SHA, rendered codepoints, font SHA, box, changed bbox). It never touches `live/`. It refuses: a box that is not plain wall (stddev gate), a font without the glyphs, an existing output. Placement is a normalised box (`render.box_norm`, override with `--box`) chosen on the real picture.
3. Script and font: Imperial Aramaic, U+10840-U+10855, one letter per Hebrew consonant (`square_exceptions.IMPERIAL`), drawn right to left letter by letter (no text shaper, so no bidi surprises), font Noto Sans Imperial Aramaic, `/System/Library/Fonts/Supplemental/NotoSansImperialAramaic-Regular.ttf`. Imperial Aramaic is the script of the period; the pointed Hebrew verse stays the text of record. Vowel points are not drawn (an ancient wall inscription is consonantal); final nun is folded to nun (Imperial Aramaic has no final forms). Layout: line 1 MENE MENE, line 2 TEKEL UPHARSIN, each read right to left.
4. Data, not code: `tools/scenes/square_exceptions.json` (only `daniel-5-1`), loader/mapping `square_exceptions.py`. Its `registry_override` replaces the registry text (which asked the generator for luminous letters) in `build_rework_jobs.py`, `gemini_web_batch.py`, and the fact card (copilot lane reads "登记要求" from it). `rework_drop_veto_notes` strips the superseded fakeText/registryFix notes from the redraw prompt. The registry file itself is untouched (read-only); the fact card was edited (backup `fact-cards/daniel-5-1.json.bak-20261103`).
5. Gate: `gate_check.check_inscription` (ids in the exceptions file only) additionally requires the inscribed evidence: bound to the current live SHA, output SHA matches the file, letters map back to exactly the verse consonants, font SHA matches. Until the inscribed file exists, `inscription_evidence_missing` keeps the square from passing. No other square is affected.
6. Tests: `tests/test_square_exceptions.py` (codepoints of the rendered string equal the verse text; only daniel-5-1 is an exception; fakeText rule unchanged; job prompt never asks for letters; composite leaves the base untouched and changes nothing outside its bbox; gate accepts good and rejects tampered evidence).
